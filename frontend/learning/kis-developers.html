KIS Developers에서 모의투자용으로 발급받습니다. 실전용 키와 섞어 쓰지 않습니다.

접근 토큰

필요할 때 서버가 발급·보관하고 만료 시 갱신합니다. 화면·로그·Git에 출력하지 않습니다.

절대 금지: App Secret, 접근 토큰, 계좌번호 전체를 이 웹사이트의 입력창·브라우저 저장소·프론트엔드 JavaScript에 넣거나 Git에 커밋하지 마세요. 이 사이트의 기존 Open API 키와 KIS API 키는 서로 다른 키입니다.
PART 1 · 계정과 키 발급

모의투자 계좌와 모의 API를 연결합니다

1

한국투자증권 계좌 개설 및 모의투자 신청

한국투자증권의 최신 안내에 따라 모의투자 참여를 신청하고 모의투자 계좌번호를 확인합니다. 실계좌 번호가 아닌 모의 계좌인지 먼저 구분합니다.

2

KIS Developers에서 모의투자 API 신청

KIS Developers에 로그인해 서비스 신청 절차에서 모의투자용 App Key와 App Secret을 발급받습니다. 발급 화면의 값은 안전한 비밀 관리 도구에 보관합니다.

3

서버 환경변수에만 저장

개발 PC에서는 .env, 운영에서는 배포 플랫폼의 Secret/환경변수에 설정합니다. .env는 버전 관리에서 제외하고, 예제 파일에는 빈 값만 둡니다.

PART 3 · 서버 환경 설정

값을 코드에서 분리해 안전하게 구성합니다

아래 값은 이 프로젝트의 .env에만 입력합니다. 실제 값을 채운 파일은 공유하거나 커밋하지 않습니다.

# KIS 모의투자 전용 — .env (Git에 커밋하지 않음)
KIS_MODE=mock
KIS_APP_KEY=발급받은_모의_APP_KEY
KIS_APP_SECRET=발급받은_모의_APP_SECRET
KIS_ACCOUNT_NO=모의계좌_앞_8자리
KIS_ACCOUNT_PRODUCT_CODE=01

Python 서버에서는 환경변수로부터만 읽고, 요청마다 모의 설정을 검증합니다. 토큰은 응답 본문이나 애플리케이션 로그에 남기지 않습니다.

import os

KIS_MODE = os.environ.get("KIS_MODE", "mock")
if KIS_MODE != "mock":
    raise RuntimeError("학습 환경에서는 KIS_MODE=mock만 허용합니다.")

KIS_BASE_URL = "https://openapivts.koreainvestment.com:29443"
KIS_APP_KEY = os.environ["KIS_APP_KEY"]
KIS_APP_SECRET = os.environ["KIS_APP_SECRET"]
KIS_ACCOUNT_NO = os.environ["KIS_ACCOUNT_NO"]
KIS_ACCOUNT_PRODUCT_CODE = os.environ.get("KIS_ACCOUNT_PRODUCT_CODE", "01")
PART 4 · 인증과 주문 구현

토큰 → 조회 → 최소 주문 순서로 검증합니다

개인·일반법인 API는 Client Credentials 방식으로 접근 토큰을 발급받습니다. KIS 공식 문서상 토큰 유효기간은 24시간이므로, 응답의 만료시각을 저장해 불필요한 재발급을 피하세요.

import requests

def get_access_token():
    response = requests.post(
        f"{KIS_BASE_URL}/oauth2/tokenP",
        headers={"content-type": "application/json; charset=utf-8"},
        json={"grant_type": "client_credentials",
              "appkey": KIS_APP_KEY,
              "appsecret": KIS_APP_SECRET},
        timeout=10,
    )
    response.raise_for_status()
    return response.json()["access_token"]  # 안전한 서버 저장소에만 보관
def order_mock_buy(access_token, stock_code="005930", qty=1, price=0):
    order_type = "01" if price == 0 else "00"  # 01: 시장가, 00: 지정가
    response = requests.post(
        f"{KIS_BASE_URL}/uapi/domestic-stock/v1/trading/order-cash",
        headers={"content-type": "application/json; charset=utf-8",
                 "authorization": f"Bearer {access_token}",
                 "appkey": KIS_APP_KEY, "appsecret": KIS_APP_SECRET,
                 "tr_id": "VTTC0012U", "custtype": "P"},
        json={"CANO": KIS_ACCOUNT_NO, "ACNT_PRDT_CD": KIS_ACCOUNT_PRODUCT_CODE,
              "PDNO": stock_code, "ORD_DVSN": order_type,
              "ORD_QTY": str(qty), "ORD_UNPR": str(price),
              "EXCG_ID_DVSN_CD": "KRX"},
        timeout=10,
    )
    response.raise_for_status()
    result = response.json()
    if result.get("rt_cd") != "0":
        raise RuntimeError(f"KIS 주문 거절: {result.get('msg_cd')} {result.get('msg1')}")
    return result
주문 API의 필수·선택 필드, 거래소 구분 및 거래 ID는 상품·API 버전에 따라 달라질 수 있습니다. 위 예시는 현재 공식 저장소의 국내주식 order_cash 구조를 학습용으로 단순화한 것입니다. 구현 전에 KIS Developers의 해당 API 문서에서 요청·응답 명세와 오류 코드를 다시 확인하세요.

처음에는 주문보다 조회와 검증을 우선합니다

순서작업성공 기준실패 시 확인
T01환경변수와 KIS_MODE=mock을 확인모의 URL만 선택됨실전 URL·TTTC ID가 설정에 없는지 확인
T02접근 토큰 1회 발급HTTP 200과 만료시각 수신모의 App Key/Secret, 서버 시각, 요청 제한 확인
T03시세·잔고 등 읽기 전용 API 호출종목·계좌 응답을 안전하게 파싱API별 tr_id·필수 파라미터·응답 코드 확인
T04장중에 1주·1건만 모의 주문응답의 rt_cd=0, 주문번호·상태 수신모의 계좌, VTTC0012U, 거래소·주문구분·수량 확인
T05미체결·체결·잔고를 차례로 조회주문 번호와 수량이 일치장 운영 시간, 체결 상태, 주문 취소/정정 가능 여부 확인
모의 REST API는 호출량 제한이 더 낮을 수 있습니다. 요청을 짧은 간격으로 반복하지 말고, 재시도에는 지수 백오프와 중복 주문 방지 키를 적용하세요. 모의 환경도 장 운영 시간에는 체결 조건의 영향을 받습니다.
