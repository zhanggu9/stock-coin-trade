01 · PREREQUISITES

배포 전에 갖춰야 하는 것

AWS 자격증명·리전

samconfig.toml은 모든 타깃을 ap-northeast-2로 고정합니다. 배포에 쓰는 IAM 주체는 CloudFormation, Lambda, API Gateway, IAM 역할 생성(CAPABILITY_IAM), S3 아티팩트 버킷, Secrets Manager 읽기, EC2 describe 권한이 필요합니다.

Secrets Manager secret

타깃마다 JSON 한 개. 템플릿은 값이 아니라 ARN만 파라미터로 받습니다. 실행 역할에는 AWSSecretsManagerGetSecretValuePolicy로 해당 ARN 읽기만 부여됩니다.

VPC · 보안 그룹 · 서브넷

DB가 private 서브넷에 있으면 Lambda도 같은 VPC의 private 서브넷 두 개 이상에 배치합니다. VPC 안의 Lambda는 인터넷이 없으므로 Secrets Manager VPC Endpoint 또는 NAT가 필요합니다.

기준 함수: arn:aws:lambda:ap-northeast-2:<ACCOUNT_ID>:function:mydbtest. 실제 AWS CLI 조회 결과 런타임은 python3.14, 핸들러는 handler.lambda_handler, 메모리는 256 MB, 타임아웃은 15초, VPC 연결은 없고 REST API mydbtest-rest-api의 /markets·/markets/{id}가 Lambda proxy로 연결돼 있었습니다. 새 함수는 mydbtest-sam으로 분리해 기존 함수를 건드리지 않습니다.

STEP 1 · B

핸들러 src/app.py

접속 정보는 환경변수(로컬) 또는 Secrets Manager JSON(AWS) 에서 읽습니다. 연결은 핸들러 밖에서 만들지 않고 매 호출 열고 닫아 DB 연결 테스트라는 목적에 맞춥니다. 비밀번호는 응답과 로그에 절대 넣지 않습니다.

src/app.py
import json, os, time
import pymysql

def _db_config():
    keys = ("DB_HOST", "DB_PORT", "DB_USER", "DB_PASSWORD", "DB_NAME")
    cfg = {k: os.environ.get(k) for k in keys}
    if all(cfg.values()):                       # 로컬: env.json 으로 주입
        return cfg
    arn = os.environ.get("DB_SECRET_ARN")       # AWS: Secret JSON 에 같은 키
    if not arn:
        raise RuntimeError("DB_SECRET_ARN 또는 DB_* 환경변수가 필요합니다.")
    import boto3
    raw = boto3.client("secretsmanager").get_secret_value(SecretId=arn)["SecretString"]
    return {k: json.loads(raw)[k] for k in keys}

def _resp(status, body):
    return {"statusCode": status, "headers": {"content-type": "application/json"},
            "body": json.dumps(body, ensure_ascii=False, default=str)}

def lambda_handler(event, context):
    table = (event.get("queryStringParameters") or {}).get("table", "")
    if table and not table.replace("_", "").isalnum():
        return _resp(400, {"ok": False, "message": "table 이름이 올바르지 않습니다."})
    cfg = _db_config()
    started = time.perf_counter()
    try:
        conn = pymysql.connect(host=cfg["DB_HOST"], port=int(cfg["DB_PORT"]), user=cfg["DB_USER"],
                               password=cfg["DB_PASSWORD"], database=cfg["DB_NAME"],
                               connect_timeout=5, cursorclass=pymysql.cursors.DictCursor)
    except pymysql.MySQLError as exc:
        return _resp(503, {"ok": False, "message": "DB 연결 실패", "error": exc.args[0]})
    try:
        with conn.cursor() as cur:
            cur.execute("SELECT VERSION() AS version, NOW() AS now, DATABASE() AS db")
            info = cur.fetchone()
            if table:
                cur.execute(f"SELECT COUNT(*) AS cnt FROM `{table}`")
                info["row_count"] = cur.fetchone()["cnt"]
                info["table"] = table
    finally:
        conn.close()
    info.update(ok=True, elapsed_ms=round((time.perf_counter() - started) * 1000, 1))
    return _resp(200, info)

STEP 2 · A

template.yaml — Lambda + HTTP API + Secret + VPC

기존 mydbtest 가 콘솔에서 눌러 만든 함수·트리거·역할·VPC 설정을 한 파일에 선언합니다. FunctionName 을 고정해 ARN 이 …:function:mydbtest-sam 이 되게 합니다.

template.yaml
AWSTemplateFormatVersion: '2010-09-09'
Transform: AWS::Serverless-2016-10-31
Description: mydbtest 와 같은 DB 연결 테스트 Lambda + HTTP API (SAM 버전)

Parameters:
  DbSecretArn:
    Type: String
    Description: DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME 키를 가진 Secret ARN
  VpcSecurityGroupIds:
    Type: List<AWS::EC2::SecurityGroup::Id>
  VpcSubnetIds:
    Type: List<AWS::EC2::Subnet::Id>

Resources:
  MyDbTestFunction:
    Type: AWS::Serverless::Function
    Properties:
      FunctionName: mydbtest-sam            # 기존 mydbtest 와 구분
      CodeUri: src/
      Handler: app.lambda_handler
      Runtime: python3.12                   # 기존 함수 런타임에 맞춤 (STEP 3 에서 확인)
      Architectures: [x86_64]
      Timeout: 10
      MemorySize: 256
      Environment:
        Variables:
          DB_SECRET_ARN: !Ref DbSecretArn   # 값이 아니라 ARN 만
          # sam local은 선언된 변수만 env.json으로 덮어쓸 수 있다.
          # AWS에서는 빈 값이므로 코드가 DB_SECRET_ARN을 사용한다.
          DB_HOST: ''
          DB_PORT: ''
          DB_USER: ''
          DB_PASSWORD: ''
          DB_NAME: ''
      Policies:
        - AWSSecretsManagerGetSecretValuePolicy:
            SecretArn: !Ref DbSecretArn
      VpcConfig:                            # DB 가 private 이면 필수
        SecurityGroupIds: !Ref VpcSecurityGroupIds
        SubnetIds: !Ref VpcSubnetIds
      Events:
        DbTest:
          Type: HttpApi                     # API Gateway v2 (HTTP API)
          Properties:
            Path: /dbtest
            Method: GET

Outputs:
  ApiUrl:
    Value: !Sub 'https://${ServerlessHttpApi}.execute-api.${AWS::Region}.${AWS::URLSuffix}/dbtest'
  FunctionArn:
    Value: !GetAtt MyDbTestFunction.Arn     # arn:aws:lambda:ap-northeast-2:<ACCOUNT_ID>:function:mydbtest-sam

SG rule + endpoint
DB_SG=sg-db   LAMBDA_SG=sg-lambda

# PostgreSQL 5432 (MariaDB 는 3306, Redis 6379, Qdrant 6333)
aws ec2 authorize-security-group-ingress --group-id $DB_SG \
  --protocol tcp --port 5432 --source-group $LAMBDA_SG

# Secrets Manager 엔드포인트 (Lambda SG 에서 443 허용하는 endpoint SG 필요)
aws ec2 create-vpc-endpoint --vpc-id $VPC_ID \
  --vpc-endpoint-type Interface \
  --service-name com.amazonaws.ap-northeast-2.secretsmanager \
  --subnet-ids subnet-a subnet-b \
  --security-group-ids sg-endpoint \
  --private-dns-enabled

이 저장소의 현재 상태: 운영 DB는 EC2 안의 Docker 컨테이너이고 외부 노출은 DB_EXTERNAL_BIND·DB_EXTERNAL_ALLOWED_CIDR로 제한돼 있습니다(DB 백업 정책 참고). Lambda를 붙이려면 ① 같은 VPC의 private 서브넷에 배치하고 EC2 SG에 Lambda SG 인바운드를 열거나 ② RDS로 옮기는 선택이 필요합니다. 이 선택이 자기주도 미션 3의 주제입니다.

09 · CI

GitHub Actions 로 타깃 배포 자동화 (설계)

현재 deploy-ec2.yml
DESIGN

현재 EC2 배포와 나란히 두는 별도 워크플로

현재 deploy-ec2.yml은 main 푸시 시 rsync + docker compose 로 EC2를 갱신합니다. Lambda 는 working/** 변경에만 반응하는 별도 워크플로로 두고, GitHub OIDC 로 AWS 역할을 맡아 액세스 키 없이 배포합니다.

.github/workflows/deploy-lambda.yml (초안)
name: Deploy Lambda (SAM)
on:
  push:
    branches: [main]
    paths: ['working/**']
  workflow_dispatch:
    inputs:
      target: { description: 'member|quant|ohlcv|session|knowledge', default: quant }
permissions: { id-token: write, contents: read }
jobs:
  deploy:
    runs-on: ubuntu-latest
    env: { TARGET: ${{ github.event.inputs.target || 'quant' }} }
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/setup-sam@v2
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_DEPLOY_ROLE_ARN }}   # OIDC 신뢰 역할
          aws-region: ap-northeast-2
      - run: |
          cd working
          sam validate --lint --template-file template/template-$TARGET.yaml
          sam build --use-container --template-file template/template-$TARGET.yaml --build-dir .aws-sam/$TARGET
          sam deploy --template-file .aws-sam/$TARGET/template.yaml \
            --config-file template/samconfig.toml --config-env $TARGET \
            --no-confirm-changeset --no-fail-on-empty-changeset \
            --parameter-overrides "${{ secrets[format('SAM_PARAMS_{0}', env.TARGET)] }}"
NOTES

CI 에서 달라지는 점

대화형 guided 는 못 쓰므로 파라미터를 Secrets 에 넣고 --parameter-overrides로 전달합니다. changeset 확인도 끕니다. 배포 후 스모크 테스트를 같은 잡에 붙입니다.
