SAM 활용 3 — 저장소 Docker DB를 Lambda·API Gateway에 연결

이 저장소는 별도 RDS·ElastiCache를 만들지 않습니다. 로컬에서는 SAM 컨테이너가 Compose DB에 직접 붙고, AWS Lambda는 같은 VPC의 EC2 Docker 포트에 붙습니다. 배포값은 Secret ARN 목록이 아니라 커밋하지 않는 working/env/lambda.env 하나로 관리합니다.

03 · TEMPLATE

STEP 3

Secret 정책 없이 URL Parameter → Lambda Environment

다섯 템플릿 모두 같은 패턴입니다. DB 서버는 만들지 않고 기존 EC2 Docker에 접속합니다.

template/template-member.yaml 핵심
Parameters:
  DatabaseUrl:
    Type: String
    NoEcho: true
  VpcSecurityGroupIds:
    Type: List<AWS::EC2::SecurityGroup::Id>
  VpcSubnetIds:
    Type: List<AWS::EC2::Subnet::Id>

Resources:
  DatabasePracticeFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: ../lambda/member/
      Handler: lambda_member.lambda_handler
      Runtime: python3.11
      Environment:
        Variables:
          DATABASE_URL: !Ref DatabaseUrl
      VpcConfig:
        SecurityGroupIds: !Ref VpcSecurityGroupIds
        SubnetIds: !Ref VpcSubnetIds
      Events:
        Api:
          Type: HttpApi
          Properties:
            Path: /members/{member_id}
            Method: GET
! 구현 범위

04 · EC2 NETWORK

Lambda → EC2 Docker 포트 열기

EC2

컨테이너 포트 publish 확인

EC2에서 실행
# .env
DB_EXTERNAL_BIND=0.0.0.0
MARIADB_EXTERNAL_PORT=3306
QUANT_EXTERNAL_PORT=5432
OHLCV_EXTERNAL_PORT=55432
REDIS_EXTERNAL_PORT=6379
QDRANT_EXTERNAL_PORT=6333

docker compose ps
ss -lnt | grep -E ':(3306|5432|55432|6379|6333)\b'
SECURITY GROUP

인터넷 전체가 아니라 Lambda SG만 허용

AWS CLI 예시
EC2_SG=sg-ec2-id
LAMBDA_SG=sg-lambda-id
for port in 3306 5432 55432 6379 6333; do
  aws ec2 authorize-security-group-ingress \
    --group-id "$EC2_SG" --protocol tcp --port "$port" \
    --source-group "$LAMBDA_SG"
done

주의: EC2의 DB_EXTERNAL_ALLOWED_CIDR 문서 규칙과 Lambda SG 규칙을 함께 적용합니다. 0.0.0.0/0으로 DB 포트를 공개하지 않습니다. Lambda subnet과 EC2가 서로 라우팅 가능한 같은 VPC인지 확인합니다.

06 · AUTH · VERIFY

JWT 타깃과 배포 API 검증

JWT

member · session

두 API는 JWT_ISSUER와 JWT_AUDIENCE가 필요합니다. 로컬 SAM은 authorizer를 생략할 수 있으므로 인증은 배포 API에서 확인합니다.

401 / 200 확인
API_URL=$(aws cloudformation describe-stacks \
  --stack-name stock-coin-trade-member-practice \
  --query 'Stacks[0].Outputs[?OutputKey==`ApiUrl`].OutputValue' --output text)

curl -i "$API_URL/members/1"                       # 401 기대
curl -i -H "Authorization: Bearer $ID_TOKEN" \
  "$API_URL/members/1"                            # 200 기대
LOGS

완료 조건

다섯 조건을 모두 확인해야 AWS 연동 완료입니다.

✓ 로컬 invoke DB 200✓ EC2 private 주소 사용✓ Lambda SG만 DB 포트 허용✓ CloudFormation CREATE_COMPLETE✓ 배포 API 200·401 확인

현재 제한: member 로컬 MariaDB 호출은 실제 200으로 확인했습니다. AWS 종단간 결과는 유효한 EC2 private 주소·VPC 값으로 배포한 뒤 확인해야 합니다. Qdrant는 현재 인메모리 구성이라 독립 컨테이너가 준비되기 전에는 knowledge Lambda의 네트워크 연동이 완료된 것이 아닙니다.
